## 4. Manifest and ingress protocol

Selected exact auth prefix `/__bookstore_next_auth`, five POST JSON operations: `/password`, `/totp/verify`, `/step-up`, `/session`, `/sign-out`. Reuse unchanged B.2c pure schema/cookie policy and same private canonical facade, not the standalone HTTP listener. JSON UTF8≤1024bytes, exact keys/canonical encoding, Origin+Host+single X-Bookstore-CSRF:1, no CORS/preflight permission. No native SDK/signup/enroll/recovery/callback/metadata endpoints.

One dynamic security-only RSC/Action page `/__bookstore_next_security` imports EVERY exported Action; GET reads, POST invokes only declared native Actions. One inert TLS/context probe may be used for feasibility; static assets are restricted to actual build-manifest files, GET only. No login/admin/dashboard or business UI. No redirect, rewrite, image optimization, remote resource or catch-all route. Only a narrowly bounded `_rsc` framework query (when necessary/proven) is allowed on that page; no auth-route queries or callback/identity parameters. It is not identity/cache authority.

Reject raw percent/double encodings, separators/dot/backslash/case/trailing/double-slash aliases, absolute forms, illegal controls, duplicate headers, CL+TE/Transfer-Encoding/trailers/Expect/upgrades/compression and noncanonical Content-Length before Next normalization. Reject all supplied Forwarded/X-Forwarded/IP/method/URL overrides, x-action-forwarded, middleware/revalidation/internal-next control and trace/baggage injection. Bound native router-state/RSC headers to the exact inert page's permitted syntax, never actor/authorization information. Next's own generated forwarded fields do not override raw socket/Host/Origin validation.

Action raw bodies≤8192bytes and Next serverActions.bodySizeLimit8192; no widened allowedOrigins. Do NOT consume a Node stream then assume Next can reread it. Selected bounded buffering strategy must retain the original IncomingMessage/socket and, synchronously BEFORE end is emitted, use public Readable.unshift to restore the validated bounded bytes for Next's decoder. Never replay another request or saved bearer response. Real truncated/overlong/chunked/multipart/abort tests must prove replay fidelity and complete-before-operation behavior; if this fails, STOP or review an equally strict streaming design before use. Route auth JSON is validated before native operations; malformed Action wire grammar is rejected before Next can print raw payload diagnostics. IMPORTANT pinned-adapter distinction: raw preconsumption is for native Page Actions ONLY, not Route Handler requests. NodeNextRequest.body passes the original IncomingMessage directly into Undici/NextRequest, whose disturbed-stream protection rejects a previously read stream despite byte unshift. Auth Routes therefore leave the body UNREAD for Next, with exact CL≤1024/no TE/absolute receive bounds already enforced by raw ingress; the Handler awaits exact bytes then strict fatal-UTF8/canonical schema and complete/cookie checks BEFORE any SQL/SDK. No private readable-state manipulation or replacement/proxy request. Native Page Actions use the separately proven pipe/Web-stream replay strategy; actual Next Action compatibility remains mandatory. This is a decoder-specific bounded design, not a relaxation of framing/body/Origin/CSRF/security-operation guards.

Known native Action IDs are read from the trusted build manifest and must all belong ONLY to the designated page. Unknown/cross-page IDs, unsupported `$ACTION_REF`/bound-argument metadata and malformed native payloads deny before dispatch. Distinguish required React protocol metadata from user fields. Pinned React19.3.1 client encodes these one-unbound-FormData-argument Flight calls as EXACT ordered multipart fields `_1_csrf` first, then `0` equal to `["$K1"]` LAST; wrong prefix/root-first/bound/REF variants deny, not aliases. This underscore prefix and streaming dependency order come from installed encoder/decoder source, not guessed JSON. Legitimate RSC prefetch/poll fixtures must use Next's maintained cache-busting hash of the actual protocol headers, NOT arbitrary `_rsc` strings: invalid hash causes a native redirect that the raw host must still reject. Neither public Action IDs nor cache-busting hashes are authentication/MFA authority. All user schemas are fixed (CSRF only); reject duplicates/File/nested/extra actor/session/permission/target/callback inputs. Actual normal multipart, enhanced Flight and direct invocation without navigation must pass; wrong-page/unknown references must produce NO internal HTTP forwarding/fetch or provider/SQL mutation. No x-action-forwarded spoof to suppress Next behavior. No redirects or post-handle cookie mutation. An owned private supervisor IPC diagnostics operation may return ONLY bounded process counters (one service publication, ingress count, TLS errors, outgoing HTTP count); no identifiers/URLs/credentials/errors/commands/selectors. Subscribe to Node HTTP/Undici request diagnostic channels without reading payloads, so actual positive native/Flight probes and wrong-reference denials must show zero outgoing HTTP requests (no hidden forwarding/redirect fetch). This observation is not identity/admission authority and is never an HTTP endpoint.

Resource limits are fixed/small: max header8192bytes/48headers,32connections,16inflight/queue0, body/header/TLS/response deadlines and cheap local256/minute cap; existing shared120/15min PG ingress plus account5-password/10-MFA and20common-IP-per-kind/native rules remain ON. Same conservative unknown-loopback scope across processes; no claimed human IP separation. Independent scenarios may recreate servers; never reset counters within a tested attack/epoch.

## 5. Cookie/CSRF/no-cache ordering

All five native cookie names/scopes stay Secure/HttpOnly/Strict/host-only/Path=/; helpers clear-only, no Domain/cache authority. Password starts empty native state and clears old scopes. TOTP/step-up applies native response updates to the ENTIRE canonical jar and consumes original ready evidence against the FINAL effective credential BEFORE Next emits any cookie/success. Discard new cookies on failure; no evidence/OTP/token in JSON/HTML/Flight/URLs/artifacts. B.2c signout cancellation commits before native deletion and independently witnesses known live row absence; no cross-client held locks or all-device/unknown anonymous-context promise. Response abort cleanup is denial-only; no exactly-once delivery fiction.

RSC uses async cookies() read ONLY; no session refresh/cache/touch or cookie writes. Every protected response/Flight/Action is private,no-store; cacheComponents/partialPrefetching disabled for this harness, force-dynamic/revalidate0/fetch-no-store, no shared tagged/fetch/function guard cache, no private data streamed before the live guard. Outer response boundary must preserve no-store even if framework code attempts override; tests inspect actual bytes/headers and cross-user responses. Session polling/prefetch/render/probe Actions never move idle/authentication/mfa/deadline origins.

Actions use a separate explicit **non-authentication anti-CSRF nonce protocol**, not B.2c's JSON-header protocol: exact raw Origin+Host+Fetch Metadata AND short-lived purpose/origin/ENTIRE-cookie-jar-bound HMAC nonce, standard maintained Node crypto/constant-time verification and independent ephemeral server-only key. Public nonce may appear in the test form/Flight: it is NOT an authentication/session token, OTP, MFA proof handle or second positive authority and cannot replace SDK/live SQL checks. Do not reuse provider secret. Generate protected-action nonces only after live guard; only deny-only signout may have a nonce for an anonymous/first-factor context. Bind to precise probe/revoke-self/sign-out purpose, immutable original cookies, bounded issuance/expiry and encoding. No cookie-derived secret/hash/provider data in nonce/plaintext. No actor-bound inline closure or target/body grant. No CSRF in URLs or new JS-readable auth cookies.

Actions: `probeAction` independently live-checks, `revokeSelfAction` uses existing no-target SQL-revalidated revocation, `signOutAction` uses existing cancellation/native deletion. Cookie clearing uses await cookies().set with every native name, empty value/MaxAge0/epoch/Secure/HttpOnly/Strict/Path=/ and no Domain, before any streaming. Never rely on the SDK nextCookies silent catch or a post-handle header. Signout storage uncertainty is explicit static unavailable result, with cookie clearing; invalid Origin/CSRF never executes cancellation or clears cookies. Action results are fixed serializable status/state/applicationAdmission-disabled only, never a raw Response/provider exception.

## 6. Bounded deny-only reconciliation

No migration is currently necessary: WORKER already has exactly five capabilities: `audit.pending_provider_events(integer)`, `audit.reconcile_provider_event(bigint)`, `audit.record_reconcile_failure(bigint,text)`, `audit.cleanup_control_orphans(integer)`, `audit.expire_control_attempts(integer)`. No new role, table/column/schema/key access, generic query/callback or grant/approval API.

A server-only worker accepts ONLY workerUrl, validates exact owned purpose/actual role/function owners+ACLs/logging, uses pool≤2 and fixed SQL/timeouts, admits at most one run at a time, selects one snapshot≤20 IDs, processes each at most once and records at most one separate fixed failure call. Overall scheduling deadline15seconds; stop scheduling rather than retry a timed-out/commit-unknown operation. Subsequent fresh process selects pending state, not a volatile/high-ID watermark. Event bigint stays a positive decimal string internally. Every event is a separate autocommit function call, never an orchestration-wide governance transaction or provider call under a held staff lock. Optional fixed expiry/orphan calls are maintenance attempts, not health certificates; their0 is indistinguishable from clock/config unavailability, expiry returns attempts only (not all deleted burns/budgets). Failure recorder returns void, not blocked count.

Return static bounded counts/status only (selected/applied/skipped/failed/uncertain/failure-record-calls-confirmed); no IDs/rows/SQL/errors/credentials, all-drained/healthy/blocked-total/rollback certainty claims. Query exceptions discard uncertain connections before failure recording; any deadline/uncertain completion cannot be reported successful. Child is separate from Next, minimal environment with ONLY worker credential and nonsecret runtime facts, strict fixed private IPC operation `security.reconcile.once`, no caller event/user/session/limit/SQL selectors, no public route. Restart/timeout/partial completion is tested; process loss never manufactures privilege.

Relevant pending/blocked transitions immediately deny live access. **session.created is intentionally non-invalidating/exempt** in accepted005/006; processing it audits/marks processed without revoking or approving. Critical credential/factor source changes ALREADY retire generation/challenges in the provider transaction; later processing cannot re-pin/reapprove/rebase. Source commit+ledger atomicity is NOT distributed source+worker atomicity. Worker local invalidation+audit+processed state is atomic/idempotent; audit failure rolls that local work back, not committed source changes. Five confirmed failure-record calls block under existing SQL semantics; failure recording outage leaves pending/denied, not repaired. Distinct out-of-order invalidations may conservatively increment/revoke separately. No grant, admission creation, autorecovery or privilege repair.
